# 3Dark — Concept

Archive app for 3D print models on macOS. Files and metadata remain fully
usable in the file system — the app is just a convenient layer on top,
never a requirement.

## Goals

- Archive all 3D models in one place, including description and print notes
- Data storage as a local folder structure, one folder per model
- Metadata in a markdown file inside each folder → readable/editable without the app
- 3D preview directly in the app
- Tagging and full filtering

## Non-Goals (deliberate)

- No database as primary storage (only as a transient index/cache)
- No cloud/server component (sync is left to iCloud Drive or similar)
- No slicer of its own, no editing of 3D geometry

## Data Storage

```
3D-Archive/                 ← freely chosen root folder
├── Benchy/
│   ├── model.md            ← metadata + description (required file, created by the app)
│   ├── benchy.stl
│   ├── benchy.3mf
│   ├── .thumbnail.png      ← generated by the app, regenerable
│   └── photos/
│       └── print-01.jpg
└── ToothbrushHolder/
    └── ...
```

Rules:

- **The file system is the single source of truth.** The app reads and
  writes only `model.md` and the files inside the folder.
- Folder name = display name (overridable via `title` in the front matter).
- External changes (editor, Finder) are detected via FSEvents and the
  index updates automatically; additionally the archive is re-read on a
  fixed 15-second interval as a fallback for volumes where FSEvents is
  unreliable (network shares, some sync services). Data is only
  published when something actually changed.
- The root folder is remembered across launches.

## Metadata Schema (`model.md`)

YAML front matter for structured data, free markdown text below:

```markdown
---
title: 3DBenchy
tags: [calibration, boat, decor]
collections: [Getting Started]
source: https://www.printables.com/model/3161-3d-benchy
author: CreativeTools
license: CC BY-ND
material: PLA
nozzle: 0.4
layer_height: 0.2
supports: no
printed: 2026-07-01
rating: 4
---

## Description

Classic calibration model …

## Print Notes

Prints fine at 0.2 mm without supports …
```

- All front matter fields are optional except `title` and `tags`.
- Legacy German keys from earlier versions (`sammlungen`, `quelle`,
  `duese`, `schichthoehe`, `stuetzen`, `gedruckt`, `bewertung`,
  `lizenz`, `autor`, `vorschaubild`) are still read and are migrated to
  the canonical English keys on the next save.
- `preview_image` (optional): path of an image file relative to the model
  folder, shown in the overview instead of the rendered 3D thumbnail —
  selectable with one click in the file list.
- `collections` groups models that belong together (e.g. a chess set).
  Membership lives with the model — a model can be in several
  collections, folder renames break nothing. Semantics: tags describe
  properties, collections describe belonging.
- Unknown fields survive saving untouched (round-trip safe).
- Date fields in ISO format (`YYYY-MM-DD`).
- List values accept semicolons in addition to commas as separators.

## Supported Formats

| Format | Archive | Preview | Implementation |
|--------|---------|---------|----------------|
| STL    | ✅ | ✅ | ModelIO/SceneKit natively |
| 3MF    | ✅ | ✅ | own parser (ZIP + XML mesh) |
| other files (photos, PDFs, …) | ✅ | images yes | grouped file list in the model detail |

## App Structure (UI)

Three-column standard layout (`NavigationSplitView`):

1. **Sidebar:** "All Models", collections, tag list with counts, rating
   filter ("N stars and up"), later smart folders. Multiple tags
   clickable → AND/OR toggle.
2. **Overview:** switchable between thumbnail grid and compact list
   (choice is remembered); search field (full text across title, tags,
   collections, description).
3. **Detail view:**
   - 3D preview (SceneKit view: rotate, zoom, reset view;
     rendered material-neutral). For multi-part assemblies the combined
     view shows all parts true to scale side by side; clicking a file in
     the list shows the single part.
   - Multi-part assemblies: one assembly = one model folder, subfolders
     (e.g. `parts/`) group the files — the file list shows them
     recursively and grouped. Quantities/notes per part as a markdown
     table in the description.
   - Metadata form (front matter fields); Enter commits changes.
     Tags & collections as chip fields: removable chips, new values via
     Enter/comma, existing values selectable from the plus menu.
   - Markdown area: rendered display, switchable to editor
   - File list with "Show in Finder" and **"Open in Cura"**; image files
     show a hover preview and can be set as the thumbnail

Thumbnails are rendered offscreen from the 3D file on first display and
stored as `.thumbnail.png` in the model folder (hidden, regenerable).

**Import (implemented):** ZIPs, folders, or single files become one new
model each via drag & drop onto the overview or the import button. ZIPs
are unpacked (single root folders are lifted, `__MACOSX` filtered out),
contained text files (txt/md/markdown, up to 512 KB) are folded into the
model.md as sections in hierarchy order and then removed from the archive
copy — no duplicated content. If the import ships a model.md, it serves
as the base (migration between archives). The source outside the archive
stays untouched.

## Technology

- Swift 5.x, SwiftUI, deployment target macOS 14+; on macOS 26 with
  Liquid Glass elements (overlay controls via `glassEffect`, material
  fallback on older systems)
- Settings (⌘,): appearance System/Light/Dark, language English/German
  (string catalog, source language English)
- SceneKit + ModelIO for STL preview; own 3MF loader
- Own minimal front matter parser (round-trip safe, instead of Yams)
- FSEvents for folder watching, plus 15 s polling as fallback
- Index: built in memory at launch (parsing the front matter of all
  `model.md` files); fast enough at this archive scale, no SQLite needed
- Distribution: locally signed app, no App Store; therefore no hard
  sandbox restrictions needed
- "Open in Cura": `NSWorkspace.open` with the UltiMaker Cura app
